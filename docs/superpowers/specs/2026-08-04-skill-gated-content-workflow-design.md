# 数字人每日视频 Skill 门控工作流设计

- 文档版本：V1.0
- 日期：2026-08-04
- 状态：业务设计已逐项确认，等待书面复核
- 关联总体方案：`docs/superpowers/specs/2026-08-04-digital-avatar-life-companion-design.md`

## 1. 核心设计原则

本项目不是把多个工具连接成无人值守流水线，而是构建一个由 Skill 驱动、用户逐步验收的交互式生产系统。

每个重要环节必须遵循同一门控模式：

```text
进入当前步骤
→ 加载该步骤的主业务 Skill
→ 主 Skill 按需调用工具型或参考型 Skill
→ 返回可审阅的结构化成果
→ 用户查看并决定
   ├─ 修改：携带反馈重新执行当前 Skill
   ├─ 重做：废弃当前版本，重新执行当前 Skill
   ├─ 退回：回到上一已完成步骤并产生新版本
   ├─ 暂存：保存状态，稍后继续
   └─ 通过：冻结当前版本并解锁下一步骤
```

未经用户明确通过，不得自动进入下一环节；已经通过的结果必须保留版本、输入、输出、Skill 版本和用户反馈，避免后续修改覆盖已批准版本。

## 2. Skill 的三层架构

### 2.1 编排层

总编排 Skill 暂定：

```text
daily-avatar-video-orchestrator
```

职责：

1. 读取每日任务和当前步骤；
2. 只加载当前步骤允许使用的主业务 Skill；
3. 准备已批准的上游产物；
4. 保存当前 Skill 的输入、输出、日志和版本；
5. 将结果呈现给用户；
6. 接收通过、修改、重做、退回或暂存动作；
7. 通过后冻结当前版本并解锁下一步骤；
8. 单个平台或外部服务失败时保留部分结果，不自动跳过验收。

### 2.2 业务层

业务 Skill 定义一个生产环节应该如何思考、执行和验收。每个业务 Skill 必须声明：

- 职责与非职责；
- 必需输入和可选输入；
- 可调用的底层 Skill；
- 输出 Schema；
- 质量标准；
- 风险与失败降级；
- 用户可执行动作；
- 进入下一步的准入条件。

### 2.3 工具与参考层

工具型 Skill 负责平台采集、TTS、数字人、Seedance、FFmpeg 等具体能力；参考型 Skill 提供成熟的方法和检查清单。参考型 Skill 不得直接覆盖主业务 Skill 的 IP、时长、原创和安全约束。

## 3. 完整逐步验收链路

| 序号 | 环节 | 主业务 Skill | 主要辅助或工具 Skill | 用户验收产物 |
|---:|---|---|---|---|
| 1 | 热点内容检索 | `daily-hotspot-research` | `hotspot-query-planner`、`opinions-crawler`、`wechat-article-search`、`channels-hotspot-research`、`hotspot-source-recorder`、`audience-comment-insight` | 《每日热点内容检索报告》 |
| 2 | 清洗与主题聚类 | `content-normalizer-and-clusterer` | `material-organizer`（辅助）、语义去重器 | 候选内容池与主题簇报告 |
| 3 | Top 3 推荐 | `life-topic-ranker` | 平台归一化热度计算、风险筛查 | 每日 Top 3 推荐报告 |
| 4 | Top 1 内容策划 | `life-companion-topic-planner` | `viral-topic-forge`、`wechat-viral-topic`（参考） | 选题策划卡 |
| 5 | 对标拆解（按需） | `benchmark-video-analyzer` | `douyin-script-analyzer` | 对标结构分析卡 |
| 6 | 原创口播稿 | `life-companion-scriptwriter` | `kidd-script-writing`（结构参考） | 可朗读口播稿及结构说明 |
| 7 | 脚本质量审核 | `life-companion-script-reviewer` | `humanizer-zh`、原创相似度、IP 与安全检查 | 脚本审核报告及终稿 |
| 8 | 分镜设计 | `avatar-seedance-scene-planner` | `scene-planner`（参考） | A-roll/B-roll 时间轴与画面计划 |
| 9 | TTS | `life-companion-tts` | 待选 TTS 工具 Skill | TTS 主音轨及音频质检报告 |
| 10 | 数字人口型 | 用户提供的数字人主 Skill | HeyGen 官方 Skill 可作为候选/备用 | 数字人口型母版及任务记录 |
| 11 | AI 场景视频 | 用户提供的 Seedance 2.0 Skill | 提示词与连续性检查 | 3–5 个 B-roll 场景片段 |
| 12 | 剪辑合成 | `avatar-video-editor` | FFmpeg、`promo-creator-skills`（规范参考） | 统一成片、字幕和合成日志 |
| 13 | 成片质检 | `short-video-quality-controller` | ffprobe、画面/音频检测 | 带时间点的问题报告或通过结果 |
| 14 | 发布包装 | `three-platform-content-packager` | 平台文案规则 | 三平台标题、简介、封面与标签 |
| 15 | 数据复盘 | `daily-video-performance-reviewer` | 人工数据导入、评分反馈 | 日报/周报与下一轮研究建议 |

上述十五个环节均允许独立验收。对标拆解属于按需步骤，可以由用户显式跳过，但必须记录跳过原因；其他环节不得静默跳过。

## 5. 第一环节：每日热点内容检索

### 5.1 环节目标

第一环节只回答：

1. 最近各平台哪些相关内容获得高互动；
2. 哪些生活问题正在多平台重复出现；
3. 30–50 岁用户正在经历哪些具体处境；
4. 用户为什么点赞、收藏、评论或转发；
5. 哪些问题值得进入下一步清洗和聚类。

第一环节明确不做：

- 不生成 Top 3；
- 不决定当天 Top 1；
- 不改写热门文案；
- 不生成口播稿；
- 不把跨平台原始点赞量直接比较；
- 不把单条高赞评论视为普遍结论。

### 5.2 主业务 Skill

```text
daily-hotspot-research
```

输入：

- 日期和时区；
- 固定受众与三个内容支柱；
- 排除主题与安全边界；
- 最近 30 天检索历史；
- 最近 30 天已制作主题；
- 平台登录和采集能力状态；
- 用户针对当天的临时要求。

输出：

- 《今日检索计划》；
- 30–40 条标准化有效来源；
- 5–8 条 A 级内容的评论洞察卡；
- 《每日热点内容检索报告》；
- 采集失败、数据缺失和可信度说明。

### 5.3 底层 Skill 组合

#### `hotspot-query-planner`：自建

每天生成 9 组核心查询：三个内容支柱各 3 组；每组包含具体场景、情绪、用户自然语言、目标平台和时间窗口。允许最多 3 组动态扩展，并读取 30 天历史避免机械重复。

重复控制：

- 完全相同关键词 7 天内原则上不重复；
- 相同生活场景 3 天内不连续作为主检索方向；
- 已制作主题 30 天内降低优先级；
- 旧话题重新升温时可标记“热点回升”后重启；
- 连续两次无有效结果的词进入 14 天冷却。

#### `opinions-crawler`：拟安装并核验

定位为多平台主要采集能力，重点验证小红书、抖音及补充平台的搜索、互动数据和评论输出。不得在真实测试前假设其已完整覆盖抖音通用视频检索；平台能力不足必须降级并在报告中说明。

运行依赖包括 Node.js 20+、Chrome/Chromium、OpenCLI 扩展和相应平台登录状态。项目当前已确认 Node.js 22 与 Google Chrome 存在，但 OpenCLI、扩展和登录状态仍待核验。

#### `wechat-article-search`：拟安装并核验

用于补充公众号深度观点、案例和背景，不作为短视频热度的主信号。

#### `channels-hotspot-research`：自建

用于视频号登录态浏览器辅助研究和人工结构化导入。未来若获得稳定的视频号专用 Skill，只替换底层适配器，不改变上层报告格式。

#### `hotspot-source-recorder`：自建

统一不同平台的数据结构，保留来源、采集时间、关键词、互动字段、原始产物路径和采集方式。它只做标准化、基础有效性检查和来源归档，不承担正式语义聚类。

#### `audience-comment-insight`：自建

对 5–8 条 A 级内容深挖评论区，识别具体场景、情绪、内心冲突、显性问题、隐性需求、用户尝试、反感表达和不同意见。

### 5.4 每日采样规模

| 来源 | 目标有效内容 | 主要作用 |
|---|---:|---|
| 抖音 | 8–10 条 | 短视频热点、钩子和传播表达 |
| 视频号 | 6–8 条 | 30–50 岁用户、家庭与熟人转发语境 |
| 小红书 | 8–10 条 | 搜索需求、收藏行为和具体处境 |
| 知乎/微博/B站等 | 4–6 条 | 观点、争议和评论补充 |
| 公众号文章 | 3–5 条 | 深度观点和事实依据 |
| 合计 | 约 30–39 条 | 某平台失败时可补足，但必须标注缺口 |

每天从其中选择 5–8 条 A 级内容，每条采集 20–40 条有效评论，总量约 100–250 条；特别高价值内容可扩展至 60 条并标记重点深挖。

### 5.5 时间窗口

以执行日为基准采用三层窗口：

| 窗口 | 比例 | 用途 |
|---|---:|---|
| 最近 72 小时 | 50% | 新近爆发和互动增长中的话题 |
| 最近 7 天 | 35% | 持续讨论和稳定高互动话题 |
| 最近 30 天 | 15% | 长尾高价值、评论区优质或近期回升内容 |

超过 30 天的内容原则上不进入当日热点池，只能进入长期素材库；如有明确的新一轮传播证据，可标记“热点回升”。

### 5.6 每日查询生成

查询采用五层结构：

1. 固定内容支柱；
2. 具体生活场景；
3. 用户情绪；
4. 用户自然语言；
5. 当日结果反向扩展词。

三个内容支柱：

- 职场打拼与现实压力；
- 子女教育与家庭沟通；
- 自我成长与人生感悟。

第一阶段继续排除“父母养老与照护压力”。搜索词不只使用“心灵鸡汤”，而应组合具体场景和用户语言，例如“被领导否定后怎么调整”“孩子越大越不愿意和父母说话”“为什么总是先考虑别人”。

各平台查询表达应适配平台语境：

- 抖音：简短情绪、冲突和话题词；
- 视频号：完整处境、家庭关系和适合转发的议题；
- 小红书：问题型、经历型和方法型搜索；
- 知乎/公众号：完整问题、原因分析和社会现象。

### 5.7 热点基础判定

第一环节从六个方面观察热点，但不提前生成 Top 3 总分：

1. 时效和互动增长；
2. 播放、点赞、评论、收藏、转发等互动信号；
3. 评论区的信息密度与真实经历；
4. 跨平台出现的相似生活问题；
5. 30–50 岁目标受众匹配；
6. 是否有明确场景、认知转折和原创扩展空间。

原始互动量必须按平台、发布时间、账号体量和内容类型解释，不能直接跨平台比较。

### 5.8 A/B/C 初步分级

#### A 级：重点深挖

符合多个条件：最近 72 小时表现突出、评论区有真实经历、目标受众高度相关、多平台出现类似问题、场景明确且有原创空间。每天选 5–8 条进入评论深挖。

#### B 级：有效热点

有互动、受众相关且场景较明确，可进入下一步聚类，但暂时缺少跨平台证据或完整评论数据。每天约 15–20 条。

#### C 级：观察素材

观点有价值但热度证据不足、数据不完整或时间较长。每天约 8–12 条，进入素材库，不一定参与当天候选。

#### 排除

来源不明、明显营销或刷量、只有空泛语录、煽动对立、搬运严重、与三个支柱无关、涉及被排除主题，或者具有专业误导风险的内容，不进入有效热点池。

### 5.9 评论采样与洞察

每条 A 级内容的有效评论建议按以下构成采样：

| 评论类型 | 目标比例 |
|---|---:|
| 高赞评论 | 30% |
| 真实经历 | 25% |
| 问题求助 | 20% |
| 不同或反对意见 | 15% |
| 最新评论 | 10% |

平台无法严格按比例返回时尽量接近，并说明限制。只有表情、简单赞美、广告、重复模板、无关讨论和无法理解的碎片内容不进入主要洞察，但应记录模板评论、疑似水军和有效信息密度低等异常。

评论洞察字段：

- 模糊用户角色与人生阶段，不收集非必要个人信息；
- 具体生活场景；
- 主要和次要情绪及强度；
- 内心冲突；
- 显性问题；
- 隐性需求：被看见、被接纳、被安慰、被解释、被指导、被陪伴；
- 用户已经尝试但效果有限的方法；
- 用户反感的说教、强行积极或不现实建议；
- 支持与反对观点；
- 少量用户原生短表达，仅用于研究，最终脚本不得拼接搬运。

评论分析不做心理疾病诊断，不推断收入、婚姻等未知信息，不把单条极端评论视为共识。涉及自伤、家暴、违法等高风险内容只做风险标记，不加工成普通鸡汤选题。

可信度：

- 高：30 条以上有效评论，场景重复出现，包含真实经历和不同意见，最好还有跨平台证据；
- 中：15–30 条有效评论，有一定共性但来源较单一；
- 低：少于 15 条、简单赞美占比高、数据不完整或只有单一高赞观点。

低可信度洞察可保留，但不得成为后续 Top 3 的主要证据。

### 5.10 《每日热点内容检索报告》

报告必须包含：

1. 检索日期、时间范围、关键词、平台和成功/失败数量；
2. 按平台展示的有效热点内容及来源；
3. 5–8 张 A 级评论洞察卡；
4. 初步跨平台热点信号，只陈述观察，不做最终排名；
5. 数据缺失、旧内容回流、账号体量、疑似刷量和版权风险；
6. 用户决策区。

用户决策动作：

```text
通过，进入内容清洗与主题聚类
补充某个平台
补充某个话题或关键词
重新采集某条内容的评论
排除某个方向
修改检索计划并重做
保存草稿，稍后继续
```

### 5.11 第一环节准入标准

只有同时满足以下条件，用户才可以批准进入第二环节：

- 获得 30–40 条有效来源，或对未达标原因有清晰说明并由用户接受；
- 抖音、视频号和小红书均有覆盖，失败平台明确标注；
- 三个内容支柱至少各有一组有效内容；
- 每条来源包含可追溯信息和采集时间；
- 5–8 条 A 级内容具备评论洞察，或缺失原因经用户接受；
- 区分 72 小时、7 天和 30 天时间窗口；
- 没有提前生成 Top 3 或脚本；
- 没有大段搬运原始文案和评论；
- 用户明确选择“通过”。

## 6. 已登记的后续候选 Skill

### 6.1 选题策划

- `viral-topic-forge`：参考热点到传播选题、标题、传播锚点和提纲的方法；必须降低制造焦虑、绝对化、强反常识和夸大表达。
- `wechat-viral-topic`：参考抖音、视频号、小红书的表达差异；本项目仍只生产一个统一成片，用它寻找三平台交集，不生成三套视频。

### 6.2 对标与脚本

- `douyin-script-analyzer`：按需拆解对标视频的钩子、结构、镜头、节奏和画面旁白关系；只提取方法，不复刻文案。
- `kidd-script-writing`：参考黄金三秒、结构推进、口语化和 B-roll 提示；不继承其知识型、强反转或固定个人文风。
- 最终原创脚本仍由自建 `life-companion-scriptwriter` 主导。

脚本主 Skill 至少支持：困境转折型、生活故事型、问题回答型、内心独白型和温和反常识型，避免每天套用同一结构。

### 6.3 分镜与制作

- `scene-planner`：参考时间轴、画面、屏幕文字、转场、动画、音乐和素材规划；由自建 `avatar-seedance-scene-planner` 增加数字人可见区间、Seedance 提示词、情绪目的和连续性字段。
- `promo-creator-skills`：只吸收制作和交付检查清单，不让商业宣传片风格主导人生陪伴内容。

### 6.4 HeyGen 官方 Skill

已登记 `heygen-avatar`、`heygen-video` 和 `heygen-translate`。它们分别适用于数字人身份、视频生成和翻译，不作为本项目脚本主 Skill。

用户后续提供的数字人 Skill 仍是优先核验对象。HeyGen 作为候选或备用通道；是否支持“固定数字人图片 + 已确认的外部 TTS 音频”并保持原始 TTS 为最终主音轨，必须在接入测试中验证。

## 7. Skill 来源与安装规则

- 第三方 Skill 必须固定仓库、路径和提交版本，不跟随未审核的最新版本自动更新；
- 安装前阅读完整 `SKILL.md`、脚本、依赖、网络访问、环境变量和写入路径；
- 需要账号、扩展、API Key 或付费额度的 Skill 必须先做能力与成本核验；
- 第三方 Skill 的输出必须经过项目 Schema 和风险检查，不直接进入下一环节；
- 参考型 Skill 不需要在每次执行时全部加载，只在主业务 Skill 判定必要时读取；
- 用户提供的数字人和 Seedance Skill 到位前，不启用真实媒体生成；
- 正式跑第一条视频前，先完成所有主业务 Skill、必要工具 Skill、版本记录和用户门控能力。

## 8. 实施顺序

1. 完成并复核本设计；
2. 为第一环节编写详细实施计划；
3. 安装和核验 `opinions-crawler`、`wechat-article-search`；
4. 自建 `daily-hotspot-research`、`hotspot-query-planner`、`channels-hotspot-research`、`hotspot-source-recorder` 和 `audience-comment-insight`；
5. 用固定样本验证报告、评论洞察和用户修改循环；
6. 用真实登录环境小规模验证小红书、抖音和视频号；
7. 第一环节验收后，再按相同方式设计和实现第二环节；
8. 所有环节和 Skill 准备完成后，才运行第一条正式端到端视频。
