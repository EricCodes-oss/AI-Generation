# 数字人人生陪伴 IP 每日视频系统设计

- 文档版本：V1.0
- 日期：2026-08-04
- 状态：总体方案已确认；Skill 门控交互设计见关联文档

## 1. 项目目标

打造一个长期运营的女性数字人 IP，每天生产 1 条 35–50 秒、9:16、1080×1920 的竖屏视频。同一无水印成片发布至抖音、视频号和小红书，仅针对各平台调整标题、简介、封面文案、标签和评论引导。

IP 定位为“温暖、清醒、不说教的人生陪伴者”，不冒充心理、教育或职场专家，不编造数字人的亲身经历。内容价值不是传统空泛鸡汤，而是：

> 看见具体处境，提供认知转折，并给出一个可以执行的小建议。

暂定精神口号：

> 生活再忙，也别把自己弄丢。

## 2. 首发受众与内容边界

### 2.1 核心受众

首个 30 天聚焦 30–50 岁、同时承担工作与家庭责任的人群。其主要压力包括职场发展、收入、子女教育、家庭沟通、年龄焦虑、自我价值和生活失衡。

### 2.2 内容支柱

| 内容支柱 | 首月比例 | 主要主题 |
|---|---:|---|
| 职场打拼与现实压力 | 35%（约 11 条） | 职场受挫、职业瓶颈、35 岁焦虑、收入压力、工作与生活边界、重新开始 |
| 子女教育与家庭沟通 | 30%（约 9 条） | 父母情绪、学习压力、青春期沟通、教育焦虑、亲子关系、家庭教育分歧 |
| 自我成长与人生感悟 | 35%（约 10 条） | 停止内耗、自我怀疑、关系边界、年龄焦虑、接受普通、重建信心 |

第一阶段明确排除“父母养老与照护压力”栏目。后续只有在用户明确调整方向时才重新纳入。

### 2.3 内容边界

- 不直接搬运平台热门文案；只研究选题、情绪、结构和评论区问题。
- 不进行心理疾病诊断、医疗建议、具体法律或财务建议。
- 不制造性别、年龄、家庭角色对立。
- 不使用“真正聪明的人都……”“你必须……”等标签化、羞辱式表达。
- 不编造数字人育儿、任职、婚姻或其他真实经历。
- 涉及教育和心理专业结论时，需保留可靠来源并进入加强审核。
- AI 生成的图像、音频和视频按现行平台及法规要求主动标识。

## 3. 平台策略

### 3.1 生产口径

每天只生产 1 个母题和 1 个统一成片，三个平台使用相同视频文件，不制作三套独立成片。

### 3.2 平台包装差异

- 抖音：突出前 3 秒钩子、评论互动、完播和关注转化。
- 视频号：突出温和完整表达、家庭或熟人转发价值。
- 小红书：突出搜索关键词、具体问题、收藏价值。

允许差异化的字段：标题、简介、封面文案、话题标签、发布时间、置顶评论。视频画面、声音和时长保持一致。

## 4. 每日内容工作流

```text
平台热门话题、搜索趋势、对标内容和用户问题采集
  → 清洗、分类和去重
  → 每日 Top 3 选题评分
  → 人工确认 Top 1
  → 原创口播稿生成
  → 自动内容安全与风格检查
  → 人工确认脚本
  → TTS 朗读稿编排
  → 独立 TTS 生成完整主音轨
  → 音频时长、读音、静音和响度检查
  → 基于实际音频生成分镜时间轴
  → 数字人图片 + TTS 音频生成完整口型母版
  → Seedance 2.0 生成 3–5 个 AI 场景片段
  → 自动合成、字幕、重点词、音乐和转场
  → 自动质量检查
  → 人工确认成片
  → 生成三平台发布包装
  → 发布并记录数据
  → 次日及周度复盘，反馈选题评分
```

生产系统采用“每一步加载对应 Skill、返回可审阅成果、用户确认后进入下一步”的门控交互。选题、脚本、成片仍是不可跳过的关键审批点，其他重要环节同样支持通过、修改、重做、退回和暂存。详细定义见 `docs/superpowers/specs/2026-08-04-skill-gated-content-workflow-design.md`。

## 5. 选题研究与评分

### 5.1 数据来源

- 抖音、视频号、小红书站内热门话题、搜索联想和热门作品；
- 对标账号及其评论区；
- 当前账号历史评论和用户提问；
- 相关权威公共资料；
- 后续经授权接入的第三方趋势数据。

采集方式必须遵守平台条款、访问频率、账号权限和版权要求。若平台没有合规 API，则首版采用登录态浏览器辅助、人工导入或半自动采样，不以规避平台限制为目标。

### 5.2 Top 3 评分

| 指标 | 权重 |
|---|---:|
| 平台热度趋势 | 20% |
| 核心受众匹配 | 20% |
| 具体生活场景 | 15% |
| 情绪共鸣能力 | 15% |
| 收藏与转发潜力 | 10% |
| 原创扩展空间 | 10% |
| 数字人口播适配 | 5% |
| 时效性 | 5% |

减分项包括版权风险、违规风险、专业误导、对立煽动、同质化和过度负面。

每个 Top 候选必须输出：选题、目标用户、具体场景、核心痛点、趋势证据、推荐理由、开场钩子、表达情绪、风险和综合评分。

## 6. 脚本设计

### 6.1 内容公式

> 具体困境 + 情绪共鸣 + 认知转折 + 微小行动 + 陪伴结尾

### 6.2 建议时间结构

- 0–3 秒：直接钩子；
- 3–12 秒：准确描述处境；
- 12–28 秒：给出新的理解角度；
- 28–42 秒：一个低风险、可执行的小行动；
- 42–50 秒：陪伴式结尾或具体互动问题。

每条只解决一个小问题。目标 TTS 音频通常控制在 40–46 秒，最终允许范围为 35–50 秒；不为凑时长添加空洞内容。

## 7. 数字人 IP 设计

### 7.1 视觉定位

- 东方女性；
- 约 32–38 岁的成熟感，不公开具体年龄；
- 知性、自然、可信；
- 温暖但有原则，清醒但不刻薄；
- 避免少女感、重网红滤镜、强广告感和过度精致。

### 7.2 人格与表达

外在关系像可靠的知心姐姐，内在是尊重用户选择的人生同行者。她不替用户做重大决定，先理解处境，再提供一个安全的小步骤。

### 7.3 视觉变化

脸、核心声音和价值观保持稳定；服装、场景、镜头、灯光、字幕节奏和情绪状态可以根据栏目变化，降低审美疲劳。

## 8. 音频与 TTS

主流程采用：

> 原创脚本 → 独立 TTS → 数字人图片 + TTS 音频 → 口型视频

“数字人图片 + 台词”仅作为故障降级方案。

独立 TTS 输出应尽量包含：音频文件、总时长、音色标识、语速/情绪参数、句级或词级时间戳。若 TTS 不提供时间戳，则使用语音识别或强制对齐补齐。

最终成片使用原始 TTS 文件作为主音轨；数字人视频中的音轨主要用于口型核验，以避免二次编码造成音质损失。

## 9. A-roll / B-roll 视频设计

### 9.1 形式

- A-roll：数字人口播，负责开头、IP 识别、核心观点、认知转折和结尾。
- B-roll：Seedance 2.0 生成的生活情境视频，负责代入、叙事和视觉变化。

配音和字幕在画面切换期间保持连续。

### 9.2 推荐比例

- 数字人：55%–65%；
- AI 场景：35%–45%。

数字人必须至少出现在开头、核心转折和结尾。

### 9.3 约 45 秒基础时间轴

```text
0–4 秒    数字人近景：核心钩子
4–10 秒   Seedance 场景：具体处境
10–17 秒  数字人：进一步共情
17–27 秒  Seedance 2–3 个场景：压力到缓和
27–36 秒  数字人：认知转折与核心观点
36–41 秒  Seedance 场景：微小行动
41–48 秒  数字人：陪伴式结尾
```

根据实际 TTS 停顿动态调整，不强制套用固定秒数。

### 9.4 Seedance 场景原则

每个提示词包含人物身份/年龄倾向、行为、场所、时间、景别、运镜、光线、色调、情绪、风格和负面约束。

- 场景全部由 Seedance 2.0 生成，不使用素材库；
- 优先背影、侧脸、中远景、手部和环境特写；
- 场景人物不正面对口型，不成为第二主持人；
- 单条视频内部保持人物、服装、空间和时间连续；
- 画面具有中国普通城市、职场和家庭生活质感；
- 前半段可以有压力，后半段逐渐平静或出现可行动的希望；
- 禁止不必要的哭喊、极端崩溃、医院意象、奢华广告感和肢体畸变。

## 10. 视频合成与质量标准

### 10.1 成片规格

- 9:16；
- 1080×1920；
- 35–50 秒；
- 无平台水印；
- 全程字幕，关键词适度强调；
- 字幕避开三个平台常见 UI 遮挡区；
- 背景音乐低于人声，使用有商业授权的音乐；
- 每 3–6 秒发生合理视觉变化，避免机械硬切。

### 10.2 自动质检

- 文件可播放、编码和分辨率正确；
- 时长符合范围；
- 无黑帧、冻结帧、异常闪烁；
- TTS 无截断、异常静音、爆音和严重机械停顿；
- 数字人口型与音频可接受；
- 字幕无明显错字、越界、遮挡和时间漂移；
- Seedance 画面无明显人物畸变、跳变或语义冲突；
- 人声响度稳定，音乐不遮盖人声；
- AI 标识和发布声明准备齐全。

若 B-roll 失败或不可用，系统可临时保留数字人母版对应画面，但必须提示人工复核；不得静默发布低质结果。

## 11. Skill 架构

| Skill | 责任 |
|---|---|
| `platform-topic-research` | 研究三平台趋势、搜索、对标内容和评论问题 |
| `content-cleaner-classifier` | 清洗、去重、分类和风险初筛 |
| `daily-topic-ranker` | 生成每日 Top 3 与推荐依据 |
| `original-script-writer` | 创作符合 IP 的 35–50 秒原创口播稿 |
| `content-safety-reviewer` | 检查相似性、误导、对立、虚假承诺和人格偏差 |
| `ip-voice-tts` | 生成固定声音、音频及时间戳 |
| `script-to-visual-storyboard` | 将脚本与音频转为 A-roll/B-roll 分镜和提示词 |
| 用户提供的数字人 Skill | 图片 + TTS 音频生成完整口型母版；图片 + 台词为备用 |
| 用户提供的 Seedance 2.0 Skill | 生成 9:16 AI 场景视频片段 |
| `daily-avatar-video-director` | 编排 TTS、数字人、Seedance、重试与任务状态 |
| `video-compositor` | 覆盖画面、字幕、音乐、转场和最终编码 |
| `video-quality-control` | 自动音画质检与问题报告 |
| `platform-publish-packager` | 生成三平台差异化发布包装 |
| `performance-analytics` | 汇总数据并反馈选题权重 |

用户提供两个生成 Skill 后，先进行能力核验，不立即批量消耗额度。核验项包括输入输出、分辨率、9:16、最大时长、参考图、音频格式、并发、生成耗时、任务查询、失败重试、费用、水印和商业使用要求。

## 12. 数据与任务状态

每日任务至少记录：

- 日期和任务 ID；
- 候选选题及评分；
- 人工选择记录；
- 原始研究来源与摘要；
- 脚本版本和审批状态；
- TTS 参数、音频和时间戳；
- 分镜、Seedance 提示词和生成任务 ID；
- 数字人任务 ID；
- 素材文件、合成版本和质检报告；
- 三平台发布包装、链接和发布时间；
- 后续播放、留存、互动、收藏、转发和关注数据。

任务状态在宏观上仍沿用 `researched → topic_approved → script_draft → script_approved → audio_ready → assets_generating → compositing → qc_failed/qc_passed → video_approved → published → analyzed`；每个宏观状态内部增加版本化 Skill 运行记录和 `waiting_for_user_approval/approved/revision_requested` 等步骤状态。

## 13. 首月验证与成功标准

连续运行 30 天，每天 1 条，三个平台发布同一成片。

首月不以粉丝数为唯一成功标准，主要验证：

1. 能否稳定完成每日一条；
2. 每日生产耗时和生成成本是否可接受；
3. 数字人形象、声音和口型是否稳定；
4. Seedance 场景与语义是否匹配；
5. A-roll/B-roll 是否优于纯数字人口播；
6. 三个内容支柱中哪个表现最好；
7. 哪类开场、情绪和行动建议最有效；
8. 用户是否产生具体评论、收藏、转发和关注；
9. 哪个平台最值得第二阶段重点投入；
10. 是否具备减少人工操作而不降低质量的条件。

重点数据：

- 抖音：3 秒/5 秒留存、平均观看、完播、互动、关注转化；
- 视频号：完播、转发、长评论、关注转化；
- 小红书：收藏、评论、搜索流量、主页访问、关注转化。

## 14. 分阶段实施顺序

1. 初始化仓库、配置、目录、任务数据结构和日志；
2. 建设选题研究、清洗和 Top 3 评分；
3. 建设原创脚本、IP 语言规范和安全审核；
4. 接入 TTS，完成音频质检和时间轴；
5. 生成分镜与 Seedance 提示词；
6. 核验并接入用户提供的数字人 Skill 和 Seedance 2.0 Skill；
7. 建设视频合成和自动质量检查；
8. 建设三平台发布包装；
9. 建设覆盖所有重要环节的 Skill 门控审批机制；
10. 运行首条端到端样片；
11. 运行 7 天小规模试产并修正；
12. 进入 30 天正式验证；
13. 根据数据决定自动化程度、栏目权重和下一阶段扩展。

## 15. V1 明确不做

- 不同时运营多个数字人 IP；
- 不每日更换数字人；
- 不制作三个平台的三套独立视频；
- 不在第一阶段纳入养老照护栏目；
- 不自动绕过平台限制抓取数据；
- 不自动无审核发布；
- 不建立心理、教育或职场专家身份；
- 不以搬运热门文案为内容生产方式；
- 不在生成 Skill 未核验前大规模消耗额度；
- 不在首版实现复杂商业化、直播或专家访谈系统。

## 16. 关键依赖与待接入项

用户后续提供：

1. 数字人视频 Skill；
2. Seedance 2.0 视频 Skill。

TTS Skill 的具体供应商、声音和参数在实施阶段通过接口能力与小样效果确定，不改变“独立 TTS 为主音轨”的架构决策。

平台采集和发布自动化程度取决于可用的合规接口、账号权限及用户提供的登录环境；若暂时无法自动化，则采用可替换的人工导入/导出适配器，不阻塞核心视频生产链路。
