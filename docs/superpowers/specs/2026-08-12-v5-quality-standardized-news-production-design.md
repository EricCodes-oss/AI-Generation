# V5标准化数字人新闻制作流程设计

**日期：** 2026-08-12  
**状态：** 已批准  
**适用模式：** 手动导演模式  
**质量基线：** `manual-run-2026-08-12-v5`

## 1. 目标

把V5成片已经验证成功的制作方法固化为项目级流程，使后续新闻视频不再依赖临时记忆和反复返工。流程既保留导演对选题、稿件、素材和节奏的判断，也通过配置、结构化记录和自动质量门阻止已知问题再次出现。

本设计解决以下问题：

- 主持人被替换、发型变化或五官质量下降；
- 未使用“未来科技解说”指定音色；
- 口播稿句子过长、内容单薄、缺少权威新闻语态或结尾不完整；
- 素材与新闻不相关、带水印或文字、动作过短、倒放、循环；
- 插播次数过多、单段太短、时间线缺少新闻节奏；
- 仅因导出MP4就误判为制作完成；
- 成片、脚本、标题、素材记录和QC证据分散，无法复现。

## 2. 范围

第一阶段只覆盖以下视频：

- 45—90秒；
- 数字人主持人主讲；
- 新闻短视频；
- 9:16竖版；
- 1080×1920、25fps；
- 无字净版；
- 默认无字幕、无标题叠加、无台标、无资料条、无背景音乐、无素材原声；
- 标题和完整口播稿作为独立文本交付。

横版视频、剧情片、宣传片、纯素材混剪和非新闻节目不在本期范围内。

## 3. 设计原则

### 3.1 事实决定口播

先建立权威事实证据包，再写口播稿。社交平台视频可以证明现场存在和视觉影响，但不能成为关键新闻事实的唯一来源。

### 3.2 语义决定画面

每段插播必须映射到明确的口播语义，并承担现场证明、影响说明或风险具象化功能。不得只为减少主持人出镜而插入泛化素材。

### 3.3 导演负责表达

自动检查负责身份、格式、时间线和技术质量。导演负责热度、新闻语态、主持人自然度、素材相关性、动作完整性和整体节奏。

### 3.4 核心资产强锁定

主持人通过ID、文件路径和SHA-256锁定；音色通过`voice_id`锁定。单次制作不得静默替换。

### 3.5 未通过质量门不算完成

导出MP4后状态只能是`rendered_pending_qc`。自动QC和导演QC全部通过后，任务才能进入`ready_to_deliver`。

## 5. 标准阶段门

### Gate 0：项目初始化

创建独立版本目录和`run-manifest.json`，锁定：

- 制作日期、主题和目标时长；
- V5质量配置版本；
- 主持人ID、参考图和SHA-256；
- 音色名称和`voice_id`；
- 输出规格；
- 无字净版开关；
- 参考视频仅用于学习结构和节奏，不复制素材、文字、音乐、台标或版式。

### Gate 1：热点资格

候选话题必须同时满足：

- 具有真实时效性和传播热度；
- 有公众利益、风险、冲突、反差或明显观看动机；
- 有权威事实来源；
- 有足够的动态现场素材；
- 不是因为“容易写”而被包装成热门。

沿用现有跨平台热点流程。没有合格热点时停止，不使用普通话题补位。

### Gate 2：事实证据包

`fact-evidence.json`至少记录：

- 权威来源和发布时间；
- 事件发生时间和地点；
- 已核实事实和数字；
- 当前状态及影响范围；
- 不确定信息；
- 禁止使用的未经证实表述。

所有口播中的日期、地点、人物、数字和结论都必须可回溯。

### Gate 3：口播稿和标题导演审核

口播稿采用权威新闻播报语态：

1. 导语直接说明最新状态和最大影响；
2. 交代时间、地点和最新进展；
3. 展开重点地区、影响范围和关键数字；
4. 使用权威口吻说明影响延续或风险变化；
5. 以完整信息自然收束。

稿件必须满足：

- 短句、单句单义、第一遍可听懂；
- 信息丰富但不堆砌；
- 后半部分仍保持新闻播报语态；
- 不使用“今天我们来看”“从公报可以看出”等旁观式套话；
- 不以“注意安全”“以上就是”等空泛表达结束；
- 最后一整句完整；
- 所有事实均有证据支持。

每条新闻交付一个正式标题和最多两个备选标题。标题通常使用“最新变化＋核心影响”的两行结构，准确、有张力但不标题党。标题默认不烧录进净版视频。

### Gate 4：声音和数字人

先生成并批准主音频，再生成数字人：

- TTS文本必须与批准稿一致；
- 固定使用指定`voice_id`；
- 检查人名、地名、数字、语速、停顿和完整收尾；
- 主音频通过后才确定最终时长；
- 数字人必须使用锁定主持人图片；
- 检查短发身份、五官清晰度、AI感、口型、表情、服装、演播室和尾部覆盖。

声音不合格只返工TTS；主持人不合格只返工数字人。两者通过前不得合成。

### Gate 5：现场素材

先按脚本语义制作素材需求表，再检索和下载。台风、暴雨类新闻优先寻找：

- 强风和树木明显摇动；
- 城市暴雨；
- 城市积水或内涝；
- 车辆涉水；
- 倒树、设施受损或其他真实影响。

可使用抖音、小红书、B站、X、新闻平台、公开素材站和用户提供的视频，也可使用正常可用的下载工具。每项素材必须保留原始页面URL。

按照用户确认的业务准入规则，素材进入制作前必须：

- 无平台水印；
- 无账号昵称、用户ID或二维码；
- 无平台角标和明显第三方Logo；
- 无烧录字幕和底部文字；
- 清晰、完整且与新闻高度相关；
- 有足够的连续动作；
- 能够支持竖版裁切。

无水印是项目的使用准入条件，但生产记录不得把它表述为已获得版权授权。

### Gate 6：镜头选择和导演时间线

下载完整素材后先生成接触表，再选择连续源区间。每个镜头必须记录：

- 来源素材；
- 源入点和出点；
- 目标时长；
- 对应口播语义；
- 动作是否完整；
- 是否正向播放；
- 清晰度和导演批准结果。

默认节奏区间：

| 成片时长 | 默认插播次数 | 单次建议时长 | 插播总占比 |
|---|---:|---:|---:|
| 45—55秒 | 2—3次 | 4.5—6.5秒 | 25%—35% |
| 56—70秒 | 3次 | 5—7秒 | 25%—35% |
| 71—90秒 | 3—4次 | 5—8秒 | 25%—38% |

上述数值是导演规划默认值，不替代语义判断。具体要求：

- 主持人先建立主题；
- 插播切点优先落在完整句子、自然停顿或语义转折处；
- 一次插播优先使用一个连续镜头；
- 不使用1—3秒碎片式频繁插播；
- 同一镜头不重复；
- 不用裁切将同一现场伪装为多个不同现场；
- 禁止倒放、循环和ping-pong；
- 最后一段必须为主持人；
- 结尾连续主持人原则上不少于全片20%，通常为10—15秒；
- 不为凑次数破坏新闻逻辑。

### Gate 7：统一渲染

渲染脚本必须可复现，并遵守：

- 1080×1920、25fps；
- H.264视频；
- AAC、48kHz、单声道主音频；
- 只映射批准的独立主音频；
- 删除素材原声；
- 素材正向连续播放；
- 仅进行必要裁切、缩放和视觉适配；
- 不添加字幕、标题、来源条、Logo或背景音乐；
- 不使用`reverse`、`loop`或ping-pong；
- 新版本不覆盖历史版本。

### Gate 8：自动技术QC

自动检查至少包括：

- 分辨率、帧率、编码器；
- 视频流和音频流数量；
- 音频采样率和声道；
- 音视频总时长；
- 时间线连续性、空隙和重叠；
- 插播次数、单段时长和总占比；
- 结尾连续主持人时长；
- 主持人ID、路径和SHA-256；
- 音色ID；
- 黑帧；
- 超过阈值的异常静音；
- 解码错误；
- 成片音频与主音频内容一致性；
- 禁止滤镜或处理方式；
- 最后一句没有被截断；
- 上一版本文件未被覆盖。

自动QC必须输出逐项证据，而不是仅输出一个布尔值。

### Gate 9：人工导演QC

导演至少完整观看两遍：

1. 第一遍不暂停，以普通观众视角判断理解、信息量、节奏、AI感和收尾；
2. 第二遍逐项检查主持人身份与五官、口型、素材相关性、切点、动作起止、水印、文字、倒放、重复、素材原声、黑帧、卡顿和尾部。

导演必须检查：

- 原始素材接触表；
- 全片接触表；
- 所有切点边界图；
- 最后15秒接触表；
- 尾部音频。

终审结果只能是`approved`或`changes_required`。

### Gate 10：统一交付

每个合格版本必须包含：

```text
video/
  final-clean.mp4
audio/
  master-voiceover.wav
copy/
  voiceover.txt
  title.txt
production/
  run-manifest.json
  fact-evidence.json
  script-review.json
  shot-selection.json
  timeline.json
  footage-ledger.json
  render.sh
qc/
  final-qc-report.json
  ffprobe.json
  blackdetect.log
  silencedetect.log
  decode-errors.log
  audio-comparison.json
  contact-sheet.jpg
  boundary-contact.jpg
  tail-contact.jpg
  sha256.txt
```

最终交付结论只能为：

- `V5质量标准通过，可交付`；
- `尚未通过，不作为最终成片交付`。

## 7. 标准数据结构

### 7.1 `run-manifest.json`

全局记录`run_id`、质量配置、主题、目标时长、主持人身份、音色ID、净版开关、父版本、状态和最终文件哈希。所有生产文件必须引用同一个`run_id`。

### 7.2 `fact-evidence.json`

记录权威来源、事件时间、发布时间、地点、已核实事实、已核实数字、不确定性和禁止表述。

### 7.3 `script-review.json`

记录脚本和标题路径、目标时长、音频实际时长、权威语态、句子清晰度、信息密度、事实可追溯性、结尾完整性和导演批准状态。

### 7.4 `footage-ledger.json`

每项素材记录平台、URL、下载时间、本地路径、SHA-256、无水印检查、无文字检查、视觉用途、源区间和用户业务准入结果。

### 7.5 `shot-selection.json`

每个镜头记录素材ID、语义功能、源入点、源出点、目标时长、连续动作、正向播放、清晰度和导演批准状态。

### 7.6 `timeline.json`

时间线必须从0开始、无空隙、无重叠，并在主音频时长结束。插播引用已批准镜头和脚本语义；最后一段必须是主持人。

### 7.7 `final-qc-report.json`

分组记录技术、身份、时间线、素材、音频、导演和交付检查。每项包含预期值、实际值、结果、证据路径和检查时间。

## 8. 质量规则等级

### 8.1 Hard Block

以下情况立即阻止流程：

- 主持人ID、路径或哈希不一致；
- `voice_id`不一致；
- 事实证据包缺失；
- 稿件未批准；
- 音频或结尾不完整；
- 数字人不是锁定主持人；
- 素材有水印、平台角标、账号标识或烧录文字；
- 素材无来源记录或无语义映射；
- 时间线有空隙、重叠或错误时长；
- 使用倒放、循环或ping-pong；
- 素材原声进入成片；
- 分辨率、帧率或音频规格不正确；
- 存在解码错误；
- 自动QC未通过；
- 导演QC未批准。

Hard Block不能通过忽略警告绕过。

### 8.2 Director Review

下列项目必须由导演判断：

- 选题是否足够热门；
- 口播是否权威、清楚且信息丰富；
- 主持人五官是否自然；
- 素材是否真正对应新闻；
- 插播次数和节奏是否合适；
- 镜头动作是否完整；
- 结尾是否自然；
- 整体是否达到V5专业新闻效果。

### 8.3 Advisory

以下情况输出建议，但不自动阻断：

- 单段插播略偏离建议区间；
- 插播占比接近上下边界；
- 开场主持人略短；
- 素材清晰度一般；
- 音频语速略快；
- 标题冲击力不足。

导演保留时必须记录原因。

## 9. 自动阻断时点

### 9.1 生成前

验证核心身份、事实包、稿件批准状态和目标时长。不通过时不得调用TTS或数字人服务。

### 9.2 素材进入时间线前

验证来源、无水印、无文字、连续源区间、语义功能和导演批准。不合格素材不能被时间线引用。

### 9.3 渲染前

验证时间线连续性、音频时长、插播规则、结尾主持人、文件存在性、哈希和禁止处理。失败时不得执行正式渲染。

### 9.4 标记完成前

验证自动QC、导演QC、文本交付、制作记录、最终哈希和历史版本完整性。仅生成MP4不得进入完成状态。

## 10. 状态模型

在现有制作状态基础上明确成片后的细分状态：

```text
compositing
  -> rendered_pending_qc
  -> automatic_qc_passed
  -> director_review
  -> ready_to_deliver
```

任一检查失败，状态返回对应生产阶段并创建新版本，不覆盖原版本。

## 11. 版本和防覆盖

目录采用：

```text
output/manual-news-YYYY-MM-DD-<topic>-v01/
output/manual-news-YYYY-MM-DD-<topic>-v02/
```

要求：

- 每版拥有独立输入、时间线、渲染脚本和QC记录；
- 修改脚本、主音频、数字人或时间线后创建新版本；
- `run-manifest.json`记录父版本；
- 最终交付明确当前批准版本；
- 历史文件哈希可复核；
- 渲染脚本默认拒绝覆盖已有成片。

## 12. 失败返工路径

| 问题 | 返回阶段 |
|---|---|
| 热点不够热门 | 热点资格审核 |
| 事实或数据错误 | 事实证据包 |
| 台词缺少权威播报感 | 口播稿审核 |
| 句子太长或内容太薄 | 口播稿审核 |
| 音色错误 | TTS生成 |
| 换脸、换发型、五官模糊 | 数字人生成 |
| 素材不相关或有文字 | 素材检索 |
| 镜头太短或动作不完整 | 镜头选择 |
| 插播频繁 | 时间线设计 |
| 倒放、循环、素材原声 | 时间线和渲染 |
| 最后一句截断 | 音频、数字人或时间线 |
| 黑帧、异常静音、解码错误 | 渲染 |
| 整体不像专业新闻 | 时间线和导演终审 |

## 13. 现有契约调整

V5实现需修正以下冲突，但不能破坏其他旧模式：

- 新配置支持45—90秒，不再沿用旧配置45—75秒上限；
- TTS和数字人契约支持90秒，或在供应商限制存在时提供安全分段方案；
- 来源信息和AI说明保存在旁路制作记录中，不烧录进无字净版；
- 主持人占比改为按成片时长和语义动态规划；
- `news-media-planner`增加连续镜头、语义映射和结尾主持人规则；
- `news-compositor`明确禁止文字、素材声、倒放和循环；
- `news-quality-control`增加身份、音频一致性、时间线、结尾和防覆盖检查。

## 14. 实现边界

推荐实现为“SOP＋可配置质量门＋导演审核”：

- 配置和模型定义质量基线；
- 验证器在生成、素材、渲染和完成前执行硬阻断；
- CLI支持初始化、预检、时间线验证和QC汇总；
- Runbook指导人工热点判断、素材下载、镜头选择和导演终审；
- 自动化不替代热点、文稿、素材和节奏的导演判断；
- 本期不实现从抓取到发布的全自动流水线。

## 15. 验收标准

实现完成后必须证明：

1. V5配置可独立加载并严格校验；
2. 主持人文件或哈希变化时预检失败；
3. 音色ID变化时预检失败；
4. 缺少事实包或脚本批准时不能进入生成；
5. 有水印、文字、无来源或无语义映射的素材不能进入时间线；
6. 时间线空隙、重叠、倒放、循环和不完整收尾均被阻止；
7. 45—90秒内可按时长给出合理插播建议；
8. 渲染前能验证所有输入和禁止处理；
9. 自动QC输出逐项检查和证据；
10. 导演未批准时不能进入`ready_to_deliver`；
11. 新版本默认不覆盖历史版本；
12. 标准交付目录、标题、口播稿、制作记录和QC报告完整；
13. V5现有成片及哈希保持不变；
14. 现有热点筛选和旧模式测试继续通过；
15. 新流程有独立runbook和自动化测试覆盖。
