# Editorial Opportunity v2 双漏斗新闻情报系统设计

**日期：** 2026-08-13  
**状态：** 已获方案方向确认，待书面规格复核  
**规则版本：** `editorial-opportunity-v2.0`

## 1. 背景与目标

项目当前已经能从多个平台采集热点并按传播性评分，但现有流程仍容易受到单一榜单、表面热度和固定候选数量的影响。胖东来门店关停与诺兰《奥德赛》两次成功制作说明，真正能够支撑高完播率的并不只是“正在上榜”，而是同时具备以下条件：

- 事件确实正在升温，而非旧闻回流或单平台营销；
- 题目存在强反差、悬念、冲突、知识缺口或与普通人的直接关系；
- 核心事实能够被权威或第一方证据支撑；
- 有真实、清晰、年代匹配且可以连续叙事的视频素材；
- 能在前三秒形成一句有信息量、能让人继续观看的开场；
- 观众看完后能够获得明确解释，而不是只获得情绪刺激。

本次升级的目标是把“发现真正值得制作的新闻”提升为项目的第一优先级，建立**先发现注意力，再判断内容价值**的双漏斗系统。系统不再为了凑数向用户展示平庸选题；没有足够强的选题时，应明确报告“暂无 S 级选题”。

## 2. 范围与非目标

### 2.1 本次范围

- 建立注意力信号与事实证据分离的数据模型；
- 支持国内榜单、权威媒体、搜索需求、社交讨论、视频传播和垂直社区六类信号；
- 建立 `30 + 35 + 20 + 15 = 100` 的编辑机会评分；
- 增加硬性淘汰规则，阻止伪热点、旧闻和事实风险题目进入候选池；
- 将用户可见候选池改为动态数量，不再固定要求 8—12 条；
- 生成导演选题卡，帮助用户与导演共同评估；
- 保留用户选题确认硬门槛；
- 更新手动模式的项目配置、报告和操作文档；
- 保留现有 `viral-v1.1` 能力作为兼容路径，避免破坏已有运行记录。

### 2.2 非目标

- 本阶段不建设完整的实时新闻数据平台或数据仓库；
- 不直接复制 GPL/AGPL 项目的源代码；
- 不把任何付费第三方 API 设为唯一数据源；
- 不在选题确认前自动进入口播、配音和视频合成；
- 不用平台热度证据替代事实证据；
- 不默认安装来源不明的第三方技能；
- 不对水印素材的可下载性作版权授权推定。

## 3. 核心原则

### 3.1 热度证据与事实证据分离

每一条证据必须明确角色：

- `attention_signal`：证明“大家正在关注什么”；
- `fact_evidence`：证明“事件事实是什么”；
- `footage_candidate`：证明“有哪些可用于叙事的真实画面”。

同一个来源可以同时承担多个角色，但系统不得因为一个话题在多个平台出现，就自动认定其事实为真。口播中的核心断言必须回到第一方、官方或至少两个独立可靠来源。

### 3.2 平台名称不机械写入口播

百度、头条、微博、抖音、小红书、B站、X、YouTube 等平台可以作为内部热度信号，但除非平台本身就是新闻事实，否则口播不得机械使用“B站上最近很火”“网上都在说”等表达。口播应直接陈述已经核验的事实与解释。

### 3.3 不凑候选数量

原始发现可以保留较大规模，但用户可见列表只展示通过内部审查的选题：

```text
20—40 个原始话题
→ 12—20 个聚类事件
→ 8—12 个内部评审事件
→ 3—8 个真正合格的用户候选
```

若只有 1—2 个选题合格，可以如实返回 1—2 个；若没有 S 级选题，必须明确报告，不得用低质量题目补齐。

### 3.4 用户确认是唯一前置人工硬门槛

系统先输出候选清单，由用户与导演共同评估。用户确认选题后，脚本、素材、配音、合成和质检按照既定手动模式流程继续执行，不再逐步请求批准，除非遇到事实冲突、素材权利风险或技术阻塞。

## 4. 双漏斗架构

## 4.1 漏斗一：热点发现

热点发现负责广泛捕捉注意力变化，不对事实真实性作最终结论。

### A. 国内榜单

支持百度、今日头条、微博、抖音、小红书、快手、知乎、B站等信号。记录榜单位置、热度值、首次出现时间、连续出现次数和跨平台扩散。

### B. 权威媒体与官方账号

支持新华网、人民日报、央视新闻、中国青年报、政府部门、公司和项目第一方账号。此类来源既可能提供早期信号，也可能提供事实证据和视频素材。

### C. 搜索需求

观察 Google Trends、百度相关搜索、解释型搜索词和问题型搜索词，例如：

- “为什么”；
- “到底是什么”；
- “一口气看懂”；
- “发生了什么”；
- “对普通人有什么影响”。

搜索需求用于识别知识缺口和“为什么是今天”。

### D. 社交讨论

观察 X、Reddit、评论区和普通用户重复提问。重点不是只计算帖子数量，而是提取：

- 高频真实问题；
- 争议点；
- 情绪变化；
- 误解与信息缺口；
- 话题所处阶段：萌芽、加速、峰值或衰退。

### E. 视频传播

观察 YouTube、抖音、小红书、B站、TikTok 等视频的上传速度、播放异常值、账号基线偏离、评论问题和字幕内容。传播异常值必须相对于账号自身常态判断，不能只比较绝对播放量。

### F. 垂直社区

按题材接入专业信号：

- GitHub、Hacker News：科技与 AI；
- Polymarket 等公开预期数据：国际与财经，只作为情绪或预期信号；
- 影视社区：文化娱乐；
- 消费投诉、教育和民生社区：普通人议题。

## 4.2 漏斗二：内容价值判断

进入第二漏斗的事件必须回答：

1. 为什么它在今天突然变热？
2. 普通人为什么需要关心？
3. 是否存在反差、悬念、冲突或知识缺口？
4. 观众看完能获得什么明确结论或解释？
5. 能否写出一句有事实含量的前三秒开场？
6. 是否存在真实、清晰、连续且语义相关的画面？
7. 核心事实能否可靠核验？
8. 热度预计还能持续多久？
9. 当前制作是否已经太迟？
10. 它是最新进展，还是没有新增事实的旧闻回流？

## 5. 数据模型

### 5.1 `AttentionSignal`

用于记录热度与传播证据：

- `source_id`；
- `source_kind`；
- `platform`；
- `captured_at`；
- `signal_url_or_reference`；
- `rank`、`engagement`、`velocity`、`account_baseline_ratio`；
- `search_growth`；
- `repeated_questions`；
- `signal_roles`；
- `raw_snapshot_path`；
- `confidence`。

### 5.2 `FactEvidence`

用于记录事实核验：

- `claim_id`；
- `claim_text`；
- `source_name`；
- `source_tier`；
- `published_at`；
- `url_or_reference`；
- `evidence_status`：`supported`、`partially_supported`、`unsupported`、`uncertain`；
- `is_first_party`；
- `independent_source_group`；
- `unresolved_conflict`。

### 5.3 `FootageAssessment`

用于记录视频潜力：

- 是否为事实相关画面；
- 是否清晰；
- 是否与事件年代匹配；
- 是否可形成连续叙事；
- 是否存在口罩、疫情年代错配、倒放、重复循环、低清等风险；
- 获取方式和权利备注；
- 可用连续时长。

### 5.4 `EditorialOpportunityScore`

固定总分 100：

#### 真实热度：30

- 跨平台共振：8；
- 排名或互动增长速度：8；
- 搜索需求增长：5；
- 异常传播内容：5；
- 持续性：4。

#### 内容吸引力：35

- 好奇缺口：8；
- 冲突、反差或悬念：7；
- 人物与现实利益：6；
- 情绪强度：5；
- 解释回报：5；
- 与普通人的接近度：4。

#### 事实可靠性：20

- 第一方或官方来源：8；
- 独立交叉验证：5；
- 时效性：3；
- 未解决断言控制：4。

#### 视频潜力：15

- 真实相关素材：6；
- 连续视觉叙事：4；
- 清晰度与年代匹配：3；
- 获取可行性：2。

每个子项保留得分、理由和证据引用。系统不得只输出一个无法审计的总分。

### 5.5 `DirectorTopicCard`

用户可见卡片字段：

- 候选标题；
- 事件最新进展；
- 为什么是今天；
- 跨平台热度证据；
- 最强反差或悬念；
- 普通人为什么关心；
- 观众看完能得到什么；
- 建议的前三秒开场；
- 可靠事实来源；
- 可用插播素材；
- 素材清晰度与年代风险；
- 预计热度寿命；
- 导演评级；
- 不推荐制作的理由。

## 6. 硬性淘汰规则

满足任一项即不得进入推荐候选：

1. 只有单个平台热度，且没有第一方突发事件豁免；
2. 核心事实没有可靠来源；
3. 没有新增进展的旧闻回流；
4. 标题很热但正文没有实质信息；
5. 只有情绪煽动，没有解释价值；
6. 没有真正相关的可用画面；
7. 核心事实仍存在未解决冲突；
8. 涉及医疗、金融或法律高风险断言且证据不足；
9. 主要由营销账号传播，缺少自然讨论；
10. 必须依靠夸张或失真标题才具有点击力。

“第一方突发事件豁免”只允许事件刚由官方首次发布、尚未形成跨平台扩散时进入观察池，不允许直接成为 S 级推荐。

## 7. 分级与候选池

### 7.1 推荐等级

- `S`：立即制作。总分建议不低于 85，且无硬性淘汰项；
- `A`：强候选。总分建议不低于 78，可与 S 级共同展示；
- `B`：观察。事实或热度尚未成熟，不进入默认用户候选；
- `DROP`：淘汰，并记录原因。

总分阈值不是绕过硬规则的方式。即使总分达到阈值，只要触发硬性淘汰，也必须降为 `DROP` 或 `B` 观察。

### 7.2 动态数量

- 内部评审上限：12；
- 用户可见推荐上限：8；
- 用户可见推荐目标范围：3—8；
- 允许少于 3；
- 禁止为了达到最低数量降低规则；
- 无 S 级选题时在报告顶部显示“暂无 S 级选题”，但可列出 A 级候选供用户判断。

### 7.3 类别多样性

类别覆盖仍包含社会民生、科技、财经、国际、政策、消费、教育、网红、普通人话题、文化娱乐、天气灾害。多样性只用于同等质量候选的排序与去重，不得为了凑类别加入弱选题。

## 8. 来源适配器注册表

建立统一来源注册表，定义：

- 来源名称与类型；
- 能承担的证据角色；
- 获取方式：现有采集器、RSS、官方 API、第三方服务或人工导入；
- 是否需要凭证；
- 可靠性等级；
- 许可与合规备注；
- 失败时的降级路径；
- 是否为实验性来源。

首批来源组：

- 国内榜单：现有百度、头条、微博、抖音、小红书、快手、知乎、B站；
- 权威来源：新华网、人民日报、央视新闻、中国青年报、政府和第一方账号；
- 聚合服务：TrendRadar、RSSHub，以服务/API 方式集成，避免复制 GPL/AGPL 代码；
- 国际方向发现：The News、GDELT；
- 社交发现：X 官方 API 优先，Xquik 作为可选适配器；
- 视频发现：YouTube Data API；
- 搜索需求：Google Trends，官方 Alpha 不可用时仅启用实验性适配器；
- 社交研究增强：ScrapeCreators 仅作为可选能力，不成为唯一依赖。

所有外部适配器必须允许失败，并回落到本地快照或人工导入流程。

## 9. 工作流

```text
采集原始注意力信号
→ 标准化与事件聚类
→ 趋势、搜索需求和异常传播分析
→ 建立事实断言清单
→ 第一方与独立来源核验
→ 素材可用性和年代质量评估
→ 硬性淘汰
→ 编辑机会评分与分级
→ 生成 3—8 条或更少的导演选题卡
→ 用户与导演共同确认
→ 进入 V5 新闻视频生产流程
→ 完成脚本、素材、配音、合成与 QC
```

选题报告必须保留原始证据路径、采集失败和评分理由，以便回溯“为什么推荐”和“为什么没有推荐”。

## 10. 与现有系统的兼容

- 现有 `viral-v1.1` 模型、报告和历史运行结果继续可读；
- 新配置通过 `rule_version: editorial-opportunity-v2.0` 启用；
- 旧配置保持原校验逻辑，新配置允许动态候选数量；
- 已有 `HotspotCandidatePool` 不直接破坏历史序列化；可新增 v2 模型或为模型增加带版本约束的兼容校验；
- CLI 保留现有命令，同时增加 v2 报告路径或在现有命令中按规则版本分派；
- 用户选题确认状态仍由现有热点选择门禁控制。

## 11. 测试策略

必须覆盖：

- 四大评分维度总权重严格等于 100；
- 热度证据与事实证据不能混用；
- 跨平台增长、搜索增长和异常传播会提高真实热度分；
- 单平台伪热点被淘汰；
- 没有新增事实的旧闻被淘汰；
- 未解决的核心事实冲突被淘汰；
- 无相关素材的选题被淘汰；
- 候选池可以返回少于 3 条，不进行弱候选补齐；
- 无 S 级时报告明确显示状态；
- 导演选题卡包含全部必需字段；
- 来源注册表校验角色、凭证、实验状态和降级策略；
- `viral-v1.1` 历史配置和测试继续通过；
- v2 端到端 fixture 能从信号、核验、评分走到用户确认门禁。

## 12. 成功标准

本次升级完成后，项目应满足：

1. 推荐列表不再由单一百度榜单或任何单个平台主导；
2. 每个推荐题目都能说明“为什么是今天”和“观众得到什么”；
3. 每个核心事实都有可审计的事实证据；
4. 低清、年代错配或不相关素材会在选题阶段暴露，而不是剪辑阶段才发现；
5. 候选数量由质量决定，系统敢于报告没有 S 级题目；
6. 用户确认题目后，可无额外逐步审批地进入成熟的视频生产流程；
7. 胖东来式“强反差”和《奥德赛》式“知识缺口 + 为什么现在”能够在评分与选题卡中被明确识别。

## 13. 风险与控制

- **平台接口不稳定：** 适配器可失败，保留本地快照和人工导入；
- **第三方服务许可风险：** 优先调用服务，不复制 GPL/AGPL 代码，并记录许可证；
- **社交热度被操纵：** 结合账号基线、跨平台自然讨论和权威事实核验；
- **评分看似精确但主观：** 每项分数必须附理由和证据，保留导演复核；
- **追热点过晚：** 强制填写热度寿命和制作时机；
- **素材可用不等于可转载：** 单独记录来源、获取方式和权利备注；
- **错误自动化决策：** 用户选题确认硬门槛不取消。
